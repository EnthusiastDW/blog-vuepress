这个问题来源于在看面试题时，SPI的应用中有日志框架，好奇它是怎么实现的，跟普通的实现是不是一样的。

我们经常通过@Slf4j来方便的引用日志框架，@Slf4j是Lombok中的，主要是为了简化代码，它会生成一下代码：
```java
public class LogExample {
      private static final org.slf4j.Logger log = org.slf4j.LoggerFactory.getLogger(LogExample.class);
  }
```

## 背景知识 SPI

SPI叫做Service Provider Interface，它不像API接口和实现都在提供方，SPI的接口和实现可以分开。就可以实现使用方定义接口，其他第三方进行实现，使用方只用引入对应的jar包就可以。

### 有什么用？
解耦，没有侵入性；
比较灵活，可以随意切换不同的实现。

### 怎么实现的？

其实很简单，通过包扫描来找到对应的实现。
1. 实现方需要resources/META-INF/services/目录中创建以接口全类名为文件名的文件，文件内容为具体的实现类全类名。多个实现换行即可，可以用#来进行注释。
2. jdk中提供了对应的方法来获取所有的实现类：`java.util.ServiceLoader.load(xxx.class)`


## slf4j的实现

也是类似的，LoggerFactory获取的是SLF4JServiceProvider接口的实现，默认获取第一个实现。通过`SLF4JServiceProvider#getLoggerFactory`获取logger工厂类ILoggerFactory的实现，再通过`ILoggerFactory#getLogger`获取最终的Logger对象。
```java
List<SLF4JServiceProvider> providersList = findServiceProviders();  
reportMultipleBindingAmbiguity(providersList);  
if (providersList != null && !providersList.isEmpty()) {  
    PROVIDER = providersList.get(0);  
    // SLF4JServiceProvider.initialize() is intended to be called here and nowhere else.  
    PROVIDER.initialize();  
    INITIALIZATION_STATE = SUCCESSFUL_INITIALIZATION;  
    reportActualBinding(providersList);  
}
```
logback-classic包中可以找到配置的实现为`ch.qos.logback.classic.spi.LogbackServiceProvider`
ILoggerFactory的实现为LoggerContext，它负责保存所有的Logger对象。

所以这就是为什么我们创建项目的时候需要引入两个包：slf4j-api和logback-classic。

如果没有引入包含实现类的包的话，将使用NOP_FallbackServiceProvider来作为兜底，这个Provider获取的Logger对象什么都不做，不会有日志打印。

## 其他应用场景

Spring Boot的自动配置和Dubbo都有采用SPI的设计思路，只不过都是用自己设计的扫描方案：META_INF目录不同，多个实现的处理不同等，基本思想是通的。通过这种方式可以方便的实现bean自动配置。
